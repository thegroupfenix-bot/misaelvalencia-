01 Hallazgos HIGH Corregidos (7 / 7)
H1
Ownership Validation — Acceso cruzado entre usuarios Agentes podían acceder y modificar operaciones, tareas y documentos de otros usuarios. Se implementó canViewOperation(), canAccessDoc(), y verificación isAssigned OR isCreatedBy en tareas. Todos los checks usan ROLE_LEVEL, no strings de rol. operations.js · tasks.js · documents.js
✓ Corregido
H2
Privilege Escalation — Bypasses por nombre de rol hardcodeado requireRole("DIRECTIVO") fallaba porque el seed usa "DIRECTOR". El array ["DIRECTIVO","SUPER_ADMIN","CORPORATE_ADMIN","DIRECTOR"] en DELETE no incluía CFO ni COMMERCIAL_DIRECTOR. Todo reemplazado por requireLevel(N) y ROLE_LEVEL. documents.js · media.js
✓ Corregido
H3
JWT Payload — PII en tránsito / token no slim El JWT contenía nombre, email, departamento y otros campos PII. Ahora emite solo {sub, id, username, role}. El middleware hace DB lookup en cada request y enriquece req.user con datos frescos — garantiza revocación inmediata de usuarios inactivos. routes/auth.js · middleware/auth.js
✓ Corregido
H4
Audit Log Security — Sin límite, sin paginación, sin RBAC granular Un atacante podía solicitar ?limit=999999 generando una respuesta masiva (DoS potencial). requireRole() con lista de strings fue reemplazado por requireLevel(55). Límite máximo 500. Paginación por offset. Filtros username/action/doc_id/from/to solo disponibles para COMPLIANCE+ (nivel 65). routes/audit.js
✓ Corregido
H5
Structured Logging — Logger inline registraba datos sensibles El logger anterior usaba console.log sin estructura, con riesgo de incluir headers o body. El nuevo requestLogger emite JSON con ts, request_id, method, route, status, duration_ms, user_id únicamente. Nunca registra Authorization, cookies, body, PII ni KYC. middleware/requestLogger.js (nuevo) · server.js
✓ Corregido
H6
Media Security — Username bypass + categorías sin validar req.user?.username !== "mvalencia" otorgaba acceso admin basado en un username hardcodeado — bypass completo de RBAC. Eliminado. Se añadió ALLOWED_CATEGORY_PREFIXES construida desde MEDIA_CATEGORIES: uploads con categoría no reconocida retornan HTTP 400. "DIRECTOR" añadido a ADMIN_ROLES (faltaba). routes/media.js
✓ Corregido
H7
Operation Status Validation — Sin whitelist ni state machine Cualquier string de status era aceptado. Se implementó OP_STATUS_TRANSITIONS con 8 estados válidos y transiciones permitidas explícitas. El status se normaliza a uppercase antes de validar. Directores (nivel ≥70) pueden forzar cualquier transición para correcciones. Cada transición se registra en audit_log. routes/operations.js
✓ Corregido
